# ビブリオバトル投票アプリ

ビブリオバトルのイベントで使う、リアルタイム投票アプリです。
参加者はQRコードを読み取るだけで、ログインなしで投票できます。

- 📖 **読んでみたい！**
- 📕 **興味はあるけど・・購入要検討！**
- 🙅 **あんまり興味ない・・買いません！**

## 起動方法

Node.js 18 以上が必要です。

```bash
npm install
npm start
```

起動すると次のように表示されます。

```
📚 ビブリオバトル投票アプリ起動: http://localhost:3000
   同じWi-Fiの端末からは: http://192.168.1.23:3000
```

**会場で使うときは、管理画面を「同じWi-Fiの端末からは」のアドレスで開いてください。**
QRコードとURLは、管理画面を開いたアドレスをもとに作られます。localhost で開くと、参加者のスマートフォンからはアクセスできません。

### 環境変数

| 変数 | 説明 |
|---|---|
| `PORT` | 待ち受けポート（初期値 3000） |
| `DATABASE_URL` | PostgreSQL の接続URL。指定するとデータをデータベースに保存します（Render などで公開する場合は必須） |
| `PUBLIC_URL` | 公開URL（例 `https://biblio.example.com`）。指定するとQRコードはこのURLで作られます（通常は不要） |
| `SIGNUP_CODE` | 指定すると、管理者アカウントの作成に招待コードが必要になります（公開する場合は設定を推奨） |
| `DATA_DIR` | `DATABASE_URL` がない場合のデータの保存先（初期値 `./data`） |

## Render（無料）で公開する

### 1. 無料のデータベースを用意する（Neon）

Render の無料プランでは、サーバーが休止・再起動するとファイルが消えます。管理者アカウントや結果を残すため、無料の PostgreSQL（Neon）を使います。

1. https://neon.tech にサインアップします（GitHub アカウントで登録できます）。
2. プロジェクトを作成します（Region は「Asia Pacific (Singapore)」など近い地域を選びます）。
3. ダッシュボードの「Connect」から接続文字列（`postgresql://...` で始まるもの）をコピーします。

### 2. Render にデプロイする

1. https://render.com に GitHub アカウントでサインアップします。
2. 「New +」→「Blueprint」を選び、このリポジトリを選びます（`render.yaml` の設定が自動で読み込まれます）。
3. 入力を求められる環境変数を設定します。
   - `DATABASE_URL`：手順1でコピーした接続文字列
   - `SIGNUP_CODE`：管理者登録用の合言葉（自由に決めてください。アカウント作成時に入力します）
4. 「Apply」を押すと数分で公開されます。`https://biblio-vote-xxxx.onrender.com` のようなURLが発行されます。

以降は、GitHub の main ブランチに変更を push すると自動で再デプロイされます。

### 無料プランの注意点

- 15分間アクセスがないとサーバーが休止します。休止後の最初のアクセスは、表示まで1分ほどかかります。**イベント開始の数分前に管理画面を開いておいてください。** 開催中は参加者の接続が続くので休止しません。
- 休止や再起動のタイミングで参加者の接続が切れても、自動で再接続されます。

## 使い方

### 管理者

1. `/login` でアカウントを作成すると、マイルームが使えるようになります。
2. マイルームでイベントを作成します。イベントは複数作れます。
3. イベント画面に参加者用のURLとQRコードが表示されます。「QRを大きく表示」を押すと、スクリーンに映す用の大きな表示になります。
4. 「イベントを開始」を押すと、セッション1の投票受付が始まります。
5. 発表が終わったら「保存して次へ」を押し、発表者名や本のタイトルを付けて保存します。
   - 保存した結果は右側のペインに格納されます。
   - 参加者の画面の数は0に戻り、次のセッションが始まります。
   - 「保存後、次のセッションの投票受付をすぐに開始する」のチェックを外すと、次のセッションは受付停止状態で始まります。発表が始まるタイミングで「投票受付を開始」を押してください。
6. 保存済みセッションの「復元」を押すと、そのセッションが現在のセッションに戻ります。名前や票数を修正（追加投票）できます。修正したら、もう一度「保存して次へ」を押してください。
7. 「このセッションをリセット」を押すと、現在のセッションの票が0に戻ります。参加者側も0に戻り、「投票受付を開始」を押すまで投票できなくなります。
8. 「合計表示ページを開く」を押すと、プロジェクター用の画面が開きます。ボタンが押されるたびにアイコンが舞い上がり、数がリアルタイムで増えます。表示の数は「合計表示をリセット」でいつでも0に戻せます。保存済みの結果には影響しません。
9. 「イベントを終了」を押すと、保存済みのセッションを「読んでみたい！」の多い順に並べたランキングが表示されます。合計表示ページも自動でランキングに切り替わり、下位から順に1位まで発表する演出で映ります。管理画面の「ランキングを映す」「投票数の表示に戻す」ボタンで、いつでも切り替えられます。
10. 「CSV出力」で、保存済みの結果を Excel で開けるCSVファイルとして出力できます。

### 参加者

- QRコードまたはURLを開くと、3つのボタンが表示されます。
- 1つのセッションで選べるボタンは1人1つです。管理者が保存するまでは、別のボタンをタップして何度でも選び直せます。
- タップすると、アニメーション・効果音・バイブレーションで選んだことがわかります。効果音は右上の 🔊 でオン/オフできます。
- 選択はブラウザに記録されるので、リロードしても引き継がれます。
- 管理者が保存またはリセットすると選択は解除され、次の投票が始まるまでボタンは押せません。

## 構成

- `server.js` … Express と Socket.IO のサーバー（API とリアルタイム通信）
- `store.js` … データの保存（PostgreSQL または JSON ファイル）
- `render.yaml` … Render の設定
- `public/` … 画面
  - `login.html` … ログイン / アカウント作成
  - `room.html` … マイルーム
  - `event.html` … イベント管理
  - `guest.html` … 参加者の投票画面
  - `display.html` … 合計表示ページ

投票は1端末につき1票です（端末ごとのIDをブラウザに保存して判定します）。
